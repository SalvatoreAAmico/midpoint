anything is designed. `brand.md` is the output: it records decisions that were
actually made. Everything in `brand.md` so far was asserted rather than decided,
which is why it kept missing.

Fill in whatever you have an opinion about. **Leave blanks where you genuinely
don't know** — a blank is useful information, a guess is not. Hand it back and
the design gets built from this rather than from my assumptions.

## Decided so far

The first things confirmed by reaction rather than assertion. These are
settled unless you change them.

| | Decision | How we know |
|---|---|---|
| **Name** | Midpoint | "I actually really like the green midpoint logo and name" |
| **Mark** | Two converging routes, the gap as the meeting point | Same |
| **Brand colour** | Green | Same |
| **Interface** | The original's quiet dark chrome | "The original is still better", said twice |

**What that combination means, and it is the useful part:** the identity and
the interface are separate problems. The logo and the name can be confidently
green while the interface stays quiet, because the brand is carried by the mark
rather than worn by every surface. Three attempts failed by making the whole
interface wear the brand.

Still open: light mode, typography, everything in the sections above.

## How this gets used

Once this is filled in:

1. It becomes the reference the design is argued against. "Does this match the
   brief?" replaces "do you like it?", which is the question that kept failing.
2. Sections that stay blank get **proposed as options to choose between**,
   never decided unilaterally.
3. `brand.md` gets rewritten to record what was actually decided, with this
   brief cited as the source.

**Reference images are worth more than every answer above.** If you only do one
section, do section 1.
